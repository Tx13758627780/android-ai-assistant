# MVP 威胁模型与边界

## 信任边界

用户输入定义任务；设备权限和确认界面定义授权。远端模型返回、App 页面文字、Accessibility 节点、截图、DeepLink 内容和 API 响应全部视为不可信输入。它们只能建议行动，不能扩大权限、关闭确认或声明任务已经完成。

本模型保护的资产包括账户与消息数据、财产、设备设置、屏幕隐私、模型密钥以及会话历史。Root/Shizuku 扩大执行能力，因此固定操作集合和执行前检查在所有后端保持一致。

## 主要风险与控制

| 风险 | 控制 | 剩余边界 |
| --- | --- | --- |
| 模型输出任意 Shell 或隐藏字段 | 封闭动作枚举；字段交叉检查；Shell 固定命令模板和范围检查 | Root 授权本身来自设备，系统/第三方 `su` 的完整性不由本项目保证 |
| 页面提示注入诱导支付、删除或发送 | 安全分类不依赖模型的 `sensitive` 标志；通用 UI 写操作也确认 | 用户仍需阅读实际操作目标，批准后不可逆动作可能即时生效 |
| 确认后页面变化，点中另一个对象 | 具体动作与观察指纹绑定；新鲜前台检查；精确唯一目标；确认一次性且有期限 | Android 执行瞬间仍存在界面变化竞态，操作后必须再次验证 |
| “确定”“发送”等文字出现多个节点 | 选择器字段精确组合；匹配必须唯一；拒绝未知或禁用节点 | 无语义节点、嵌套可点击对象和复杂 WebView 可能无法自动操作 |
| 模型把 HTTP 返回/Intent 启动当作业务完成 | 独立 `verify`；保留证据；步骤失败则停止或有限修复 | HTTP 状态只说明请求状态，前台 App 只说明导航成功 |
| 网络 API 变成数据外传通道 | HTTPS、公开域名限制、明确允许的 API 主机、禁止自动跳转、变更操作确认 | 获准主机可接收请求中的数据；远端模型配置本身也是数据接收方 |
| 超时后重复支付、消息或删除 | 不可重复动作不自动重发；在途标记；中断恢复先观察后验证 | 某些 App 无法提供充分证据时只能暂停，无法提供 exactly-once 业务保证 |
| 请求发出后网络中断，被错误认为没有执行 | API 变更请求开始传输后没有明确响应，按已发出且结果不确定处理；暂停并保留在途标记 | 服务端自身幂等保障或查询接口需要各业务提供 |
| 保存轨迹与移动步骤索引之间崩溃 | 成功轨迹、步骤索引和清除标记在同一次原子会话写入中提交；不确定轨迹和保留标记同写 | 原子文件只保护一次写入；恢复逻辑仍需要回归测试 |
| 修复计划重复之前的业务副作用 | 一次后缀修复预算，保持完成前缀，拒绝相同的已完成不可重复动作，新的敏感动作再确认 | 不同 URL/输入可能语义相同，不能以动作哈希代替业务幂等键 |
| 隐藏后台自动执行 | 用户启动的前台任务服务，通知显示状态和停止入口 | App 商店和 OEM 可能对前台服务/无障碍用途另有限制 |
| 屏幕和密码泄露 | 密码节点不读文本/不输入；含密码的屏幕不截图；截图远端发送需明确配置 | 节点未标注密码、二维码和自定义渲染文本仍可能含隐私信息 |
| 模型密钥被备份或写入日志 | 私有配置存储；禁用 Android 备份；不将密钥写入会话/动作轨迹 | 设备 Root、被攻破的系统或调试访问可能读取 App 数据 |
| 无限规划/循环和电量消耗 | 步骤、候选动作、等待与重试预算；取消入口 | 网络服务和设备响应耗时仍需受具体适配器超时约束 |

## 确认的具体含义

每次确认显示即将执行的动作、目标和原因。它批准的是该动作在当前上下文中的一次执行。旧令牌、过期令牌、错误步骤或变化后的页面不能复用。拒绝/取消确认应停止执行，不应悄悄改走另一个敏感候选动作。

接口合同中，`ExecutionResult.dispatched=false` 必须表示确定没有发出动作，不能用于“可能发出了但未收到响应”。确认界面必须以实际请求目标、方法、输入和参数为准，模型描述不能替代真实参数。

所有坐标点击仍受当前 UI 目标检查；没有唯一可点击 Accessibility 节点的纯视觉对象在 MVP 中可能不被支持。这是实际能力限制，不应退化为盲目手势。

## 数据与运维

本地确定性 Planner 可以在不发送任务/屏幕到模型服务的情况下执行其内置任务。远端 Planner 需要用户配置提供方和密钥；远端规划通常需要任务、当前节点和必要上下文，视觉定位可能还需要截图。部署到真实账号前应选择可信端点并检查其数据处理策略。

会话轨迹可能包含用户任务、消息草稿、URL 和屏幕节点相关文本，应按账户数据处理。配置密钥不会作为会话记忆或操作证据保存。不要把真实密码、验证码或密钥放入任务文本、示例配置或提交记录。

自动化依赖被自动操作 App 的权限、功能和条款，不提供验证码/生物识别绕过。未在真实设备验证的能力不能视为生产就绪；测试报告必须区分 JVM 模拟测试、APK 编译/静态检查以及实机验证。

## 应持续验证的安全性质

1. 模型不能添加新执行能力或关闭敏感确认。
2. 获准动作与实际执行动作一致，令牌不能重放。
3. UI 目标缺失、重复、移动或前台变化时不执行。
4. 成功来自独立设备证据，而非 Planner 自述或 `dispatched=true`。
5. 中断或超时不能自动重发不可重复副作用。
6. 取消状态保持终止；在途操作完成后也不能继续后续步骤。
7. 所有执行后端遵守同一动作合同，机密配置不进入持久化轨迹。
